# Aftersales recovery

Starting point: saved v2.13.74. The missing v2.14 work was rebuilt after the environment reset.

## Implemented source

- Support can offer an inspected exchange an original-payment refund alternative only after actual receipt, completed warehouse disposition and original settlement validation. The buyer owns the explicit accept/decline decision. Proposal, acceptance and Finance review preserve the stable source hash. Acceptance records consent and a pending refund; it does not create a refund, post a ledger entry or reserve a replacement.
- Proposals cannot overwrite a previous decision. Stale versions, changed payment/inspection/receipt sources, consumed refund capacity and pending line allocations stop acceptance. Decline remains available if a source becomes unavailable. Existing support/payment services own exchange reservation, Finance referral, refund reservation/completion and residual financial calculations.
- `SpecialistReferral` records the actual order/dispute/Support-ticket handoff. Finance, Moderation and Country Admin have current market-scoped claim/respond queues; delivery and operational referrals reach Country Admin. Seller `/seller/cases` is a separate current-store order queue. Policy TrustCases remain at `/seller/trust-cases`.
- Receiving specialists must claim a pending referral and be independent of the buyer and referring Support actor. Current User, Device, grant or accepted store membership, store/market authority, source identity and source versions are fenced within writes. A specialist assessment returns private notes to Support and returns the dispute to investigation; it does not fabricate payment/delivery success or close the buyer case.
- Private uploaded response evidence is bound to its referral. Non-seller specialists may read the originally attached buyer evidence; sellers receive only their separate seller message, their own order lines and referral response evidence. Buyer names, addresses, private dispute text and internal Support notes are omitted from seller projections. Support can read the private returned assessment and evidence.
- Evidence delivery rechecks current authority, storage key, source identities and ready evidence after storage I/O, before sending bytes. Its dedicated read revisions preserve normal workflow versions.
- Customer return cards expose saved return/inspection/proposal progress. A collection code is fetched on explicit request from the current owner-and-assigned-shipment endpoint, is absent from HTML/ordinary JSON, can be hidden again and is cleared on page exit. The old pickup-code URL redirects to that endpoint. Physical collection remains in the delivery workflow.

## Integration

The current root-owned app mounts `aftersales-pages.js`; the four approved workspace templates include `specialist-order-case-forms.ejs`; registry/navigation expose the specialist queues and distinguish seller order cases from policy cases. The current customer route provides the private collection-code API. No additional missing integration was identified statically. Shared app/nav/registry/MFA files were not changed by this review.
