# Seller recovery

Recovered base: `ae09365` (v2.13.74). The previous uncommitted v2.14 tree was lost; this note records the replacement work as it lands.

Owned scope: store team invitations and explicit workspace selection (G19), Seller affiliate campaigns (G20), independently reviewed subscription billing and typed entitlements (G21), and private Seller policy case responses/appeals (G05).

The approved Final19 shell, colors, spacing and shared CSS remain unchanged. Root wires route mounts, registry and approved-shell partial selection. Runtime checks, database processes and commits are root-owned.

Implemented contracts:

- Team: `/seller/team` invites or revokes store capabilities; `/account/store-invitations` is the exact verified-email recipient inbox. Acceptance is versioned and transactional, rechecks the inviting account/token/membership/permission revision, and does not change the recipient's identity role or select a store. `/seller/workspace` explicitly selects an accepted workspace. Owner membership and self-access are protected; only owners appoint administrators. Pending unexpired invitations reserve seats. Role changes revoke outstanding invitations issued by that member. Outbox delivery decrypts the address only after current authority is rechecked; unavailable invitations are cancelled and development sinks are labelled.
- Access and settings: `sellerOperationsAccess` rechecks current account/device, accepted membership, capability, real owner and active country/currency; mutations fence those sources in the transaction. Settings reads use that boundary, and settings mutations compare the submitted Store revision before the shared fence, update only allowed fields, advance the Store revision once and commit an audit atomically. Supplier access requires an explicitly selected staff workspace and a current active Seller owner with no platform management/grants; the owner default can select only their own store.
- Affiliate: `/seller/affiliate` owns draft/edit/submit/pause/resume/end and promoter application decisions. Products must belong to the store and be approved in its country. Publication requires a separate Country Admin decision with conflict checks; a public Seller campaign still requires Seller approval of each independently verified promoter application. Ending or revoking disables links. A Seller resume only applies to their own pause of an independently approved campaign. Submission queues a Country Admin alert from the persisted campaign source with product/store linkage checks.
- Billing: subscription requests freeze typed plan terms and require independent Super Admin review before payment. A payment fixes the reviewed price and terms, uses an idempotency key, and treats an ambiguous provider submission as held rather than submitting twice. Provider return/IPN/reconciliation fetches Pesapal status and checks exact reference, tracking ID, currency and minor amount. Verified money posts an idempotent ledger transaction; activation rechecks owner, market, approved snapshot and current payer authority. Held activation can be explicitly authorized by the current owner; unresolved tracking references require independent Super Admin reconciliation. Renewals buy one immutable future period; cancellation preserves the paid period, maintenance expires it, and verified reversals remove its paid benefits with one ledger reversal.
- Entitlements: product/seat/campaign capacity and analytics permissions derive only from current immutable enrollment snapshots linked both ways to their settled, unreversed subscription charge. Legacy or fabricated enrollment labels grant no paid benefits. Capacity mutations share the Store write fence, so competing last-seat/product/campaign writes cannot both succeed.
- Policy cases: `/seller/trust-cases` is separate from aftersales `/seller/cases`. Store owners/admin/support can read the actual privately scoped concern, respond or record a correction, attach sanitized private images, and submit one eligible appeal with the original decision maker preserved for independent review. This private workflow remains available while commerce is suspended. Projections omit reporter identities and moderation-only notes; evidence delivery rechecks store/case/response attachment and current authority.
- Seller offers in checkout: `promotionQuote({ rows, country, codes, session })` retains its existing public quote DTO. With a transaction session, it reads promotions in that transaction and takes a private `checkoutReadRevision` write fence for every actually applied price or free-shipping offer, rechecking its source revision and active window. The fence changes neither the Seller form revision nor the displayed update time.

The recovered team, affiliate, policy and billing partials now initialize their own EJS locals from `pageFlow`, preserving the approved shell and shared styles.

Runtime handoff: root owns all jobs. Its first live run passed the real local-Pesapal immutable billing/idempotency case, renewal case and recipient/team/workspace case. That run exposed an unsupported campaign alert source, missing policy partial locals and the Mongoose 9 pipeline option in expiry maintenance; those source defects are fixed. `test/seller-recovery-live.test.js` additionally covers all new HTML form pages and settings/supplier current-authority rejection and rollback. Older `seller-settings-authority-live` and `seller-store-live` fixtures now include active market settings, current device/session/token state and accepted memberships; the Customer catalogue staff fixture explicitly selects its store, while all prior stale-version, isolation and rollback assertions remain. Suspended settings GET (including trailing slash) retains its locked approved UI, while edits still fail. Root rerun is pending; no final runtime-pass claim is made here.
